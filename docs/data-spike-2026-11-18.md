# Data Spike: แหล่งข้อมูลประกาศงานสำหรับหัวข้อ E′ (18 พ.ย. 2569)

> **เป้าหมาย:** ทดลองดึงข้อมูลจริงก่อนล็อกหัวข้อ "Skill Demand Intelligence (ประกาศงานทั้งประเทศ)" ว่าข้อมูลหาได้จริง พอสำหรับคลังข้อมูลและ ML หรือไม่ และควรใช้แหล่งไหน
> **ขอบเขตการทดลอง:** ดึงตัวอย่างเล็กๆ เท่านั้น ทีละ 1 request เว้น 5 วินาที ใช้เฉพาะ path ที่ robots.txt อนุญาต ไม่ใช้ API ภายในของเว็บ ไม่หลบการตรวจจับ และตัดข้อมูลผู้ติดต่อ (โทรศัพท์/อีเมล) ทิ้งตอน parse
> **ไฟล์:** สคริปต์อยู่ใน `spike/scripts/`, ข้อมูลดิบใน `spike/raw/` (**ห้ามเผยแพร่หรือ commit ขึ้น public repo**), ผลวิเคราะห์ใน `spike/out/`

## 2. เว็บประกาศงาน

| เว็บ | robots.txt | เงื่อนไขการใช้งาน (ToS) | ข้อมูลแบบมีโครงสร้าง | จำนวนประกาศ | ผล |
|---|---|---|---|---|---|
| **JobThai** | `Allow: /` อนุญาตหน้าประกาศ | ห้าม "ทำซ้ำ คัดลอก ... เพื่อเผยแพร่ต่อสาธารณชน หรือเพื่อหาประโยชน์" โดยไม่ได้รับอนุญาตเป็นลายลักษณ์อักษร | ✅ schema.org `JobPosting` ครบ: ตำแหน่ง, รายละเอียด, คุณสมบัติ, เงินเดือน min–max, จังหวัด/อำเภอ, หมวดงาน, อุตสาหกรรม, ประเภทการจ้าง, วันที่ประกาศ | **48,438** (ทั้งประเทศ ณ วันทดลอง) | ✅ **แหล่งหลัก** ใช้ได้ภายใต้เงื่อนไขการแสดงผล (ข้อ 6) |
| **JobBKK** | อนุญาตหน้าประกาศ | ห้ามคัดลอก "เพื่อแสวงหาผลประโยชน์ทางการค้า" | ✅ `JobPosting` + วันหมดเขต + ที่อยู่ | ไม่ทราบ (หน้าแรกแสดงตัวเลขการตลาด "100,000 ตำแหน่ง") | ⏳ **แหล่งที่ 2 (ภายหลัง):** หน้ารายการโหลดด้วย JavaScript ต้องใช้ Playwright |
| **JobTopGun** | อนุญาต `/jobs/` | **ข้อ 3.3 ห้าม screen scraping, data mining, robots และการรวบรวมข้อมูล** เว้นแต่ได้รับความยินยอมล่วงหน้าเป็นลายลักษณ์อักษร | ✅ ละเอียดที่สุด (มีวุฒิการศึกษาและจำนวนเดือนประสบการณ์) | ~7,816 | ❌ **ห้ามใช้** (ตัวอย่างที่ดึงไปก่อนอ่าน ToS ถูกลบแล้ว) |
| **JobsDB (SEEK)** | `Disallow: */job/` สำหรับทุก bot และห้าม `anthropic-ai` โดยเฉพาะ | — | — | — | ❌ ห้ามใช้ |
| **Indeed TH** | ซับซ้อน, มีระบบกัน bot | ไม่ได้ตรวจลึก | — | — | ❌ ไม่ใช้ |

**ข้อค้นพบทางเทคนิคของ JobThai:**
- หน้าประกาศใช้ Next.js และฝัง `JobPosting` JSON-LD ไว้ใน `self.__next_s` ทำให้ parse ได้ตรงโดยไม่ต้องพึ่งโครงสร้าง HTML (เปราะน้อยกว่า)
- **Sitemap ล้าสมัย** (`lastmod` เม.ย. 2569) ประกาศจาก sitemap ที่ลองเปิดหมดอายุแล้ว จึงใช้ sitemap หาประกาศปัจจุบันไม่ได้
- **หน้ารายการ "งานทั้งหมด" ไม่สนใจเลขหน้า** (หน้า 1, 300, …, 2100 ได้ 20 ประกาศชุดเดียวกัน) แต่ **หน้ารายจังหวัด `?province=XX` ใช้ได้** และมีจำนวนประกาศรวมของจังหวัดนั้น
- การเก็บข้อมูลจริงจึงต้องใช้ Playwright เลื่อนหน้ารายการรายจังหวัด/รายหมวด หรือขออนุญาต JobThai เพื่อเข้าถึงข้อมูลโดยตรง

## 6. การตัดสินใจ

**ตัดสินใจ: ล็อกหัวข้อ E′ "Skill Demand Intelligence" ใช้ JobThai เป็นแหล่งหลัก**

### เหตุผล
1. **ข้อมูลโครงสร้างพร้อม:** `JobPosting` JSON-LD ให้ฟิลด์หลักครบ 100% และ parse ได้ 131/131 โดยไม่ต้องพึ่ง HTML
2. **ปริมาณพอ:** 48,438 ประกาศเปิดอยู่ทั้งประเทศ; ถ้าเงินเดือนเป็นตัวเลข ~56% → ประมาณ **48,438 × 0.56 ≈ 27,000 แถวที่ใช้ทำ ML เงินเดือนได้** (ตัวเลขทางทฤษฎีของทั้งตลาด; ตัวอย่างที่เก็บจริงจะน้อยกว่า ตามเวลา scrape: ที่ ~600 ประกาศ/ชั่วโมง เก็บได้ 5,000–10,000 ประกาศใน 8–17 ชั่วโมง ให้แถวมีเงินเดือนราว 2,800–5,600 แถว ซึ่งเพียงพอ)
3. **ข้อมูลภาคใต้ไม่พอ** (14 จังหวัดรวม 1,161 ประกาศ = 2.4%) → ต้องใช้ข้อมูลทั้งประเทศ และทำให้ "ตลาดแรงงานทั่วประเทศ" เป็นกรอบโครงงานที่ถูกต้อง
4. **ทักษะดึงได้:** 99% ของประกาศมีทักษะ ≥ 1 ด้วย dictionary เริ่มต้น แสดงว่าแนว dictionary + alias ใช้ได้ (ไม่ต้องใช้ LLM)
5. **ข้อมูลภาครัฐเป็นเพียงบริบท** ไม่ใช่แกนของคลังข้อมูล

### ผลต่อการออกแบบ
| เรื่อง | การตัดสินใจ |
|---|---|
| การแสดงผล | **aggregate เท่านั้น + ลิงก์ไปประกาศต้นฉบับ** ไม่แสดงข้อความประกาศ (ToS ห้ามเผยแพร่ซ้ำ) |
| Taxonomy | **สร้างเอง** (canonical skill + alias ไทย/อังกฤษ) เพราะชื่อ O*NET แบบเป๊ะตรงเพียง 5/21 ประกาศ และ ESCO ไม่มีภาษาไทย; เริ่ม 100–200 ทักษะ ขยายจากคิว alias ที่ admin ตรวจ |
| ML เงินเดือน | ทำได้เฉพาะแถวที่มีเงินเดือนเป็นตัวเลข (~56%) ต้องแปลงหน่วย (วัน → เดือน) และรายงาน selection bias; GroupKFold ตามบริษัท; **ไม่ใช้เพศ/อายุ** (27% / 58% ของประกาศระบุไว้) |
